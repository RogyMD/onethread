# Onethread v1.0.0 Release Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to carry out this plan after the owner approves it.

**Goal:** Publish onethread as a trustworthy public v1.0.0 GitHub release that a new Mac user can install, understand, and use with Claude Code or Codex.

**Architecture:** Release the existing local-first Python CLI from `main` as source code, using an annotated `v1.0.0` tag and GitHub Release notes. Do not add a package manager, binary installer, hosted service, or new product features as part of release preparation.

**Tech Stack:** Python 3.9+ standard library, Git, macOS, Claude Code and/or Codex CLI, optional iTerm2; GitHub for the public source and release page.

**Spec:** Current product contract in `README.md`, `HOW-IT-WORKS.md`, `docs/ARCHITECTURE.md`, and `docs/STATUS.md`.

## Global Constraints

- Python 3.9+ and the standard library only.
- Onethread stays local-first, with no server, telemetry, or account of its own.
- Claude Code and Codex are the supported agent CLIs; iTerm2 is recommended for task tabs and banners.
- User approval is required for consequential actions, including publishing the release.
- Do not publish personal data, secrets, conversation logs, or private task output.
- Do not rewrite public Git history unless the owner explicitly approves that separate action.
- Do not create a public tag, push `main`, or create the GitHub Release before 2026-10-31; the owner plans to publish tomorrow, and final go-ahead is still required.

## Review Focus

- Real Claude and Codex workers: confirm task start, completion, review, acceptance, and session recovery behave as documented.
- New Mac setup: install from a fresh clone with Python 3.9+, and confirm the documented behavior when iTerm2 is absent.
- Worker boundaries: verify the documented sandbox limits and the known risk from running a repository's own test/build scripts.
- Owner data safety: check worktree cleanup, ignored files, notifications, and confirmation prompts against the documented behavior.
- Public identity and history: inspect current files and the complete commit history for secrets, private details, and author information the owner may not want public.
