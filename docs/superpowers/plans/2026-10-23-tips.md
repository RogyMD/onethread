# Tips Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** At most once a day the orchestrator notices something the owner (or it) repeated, offers one fix, and remembers the answer; preferences the owner accepts shape every orchestrator window from then on.

**Architecture:** `ot` has no AI: a new `onethread/tips.py` holds the journal (every `ot` command, in the events table), the 24-hour gate, declined/accepted tip keys (meta), and the preferences file (`<home>/preferences.md`). The prompt hook adds the preferences and, when the gate is open, a "tip slot" line; the lobby INSTRUCTIONS tell the orchestrator what to do with them. `ot repo new PATH` lets a CraftApps tip start a project.

**Tech Stack:** Python 3.10+ standard library, unittest, SQLite, git.

**Spec:** `docs/superpowers/specs/2026-10-22-finish-and-tips-design.md`, Part 2, the anti-goals, and the "Calls settled" lines on CraftApps tips and safety rules.

## Global Constraints

- Standard library only; nothing sent off this machine.
- `ot` never reads Claude or Codex session or history files; the journal holds only `ot`'s own commands (command name, task id, first 80 characters of the arguments).
- At most one tip per 24 hours (`DAY = 86400`), never a declined tip again, never acting on a tip without the owner's yes.
- `<home>/preferences.md`: plain text, one preference per line, the owner may edit it by hand.
- A preference never overrides a safety rule: the native confirmation dialogs, no push or publish, no reading Claude/Codex history, never deleting unmerged branches or dirty worktrees.
- The owner never types these commands; the orchestrator runs them.
- Journal entries are kept 30 days.
- Update README, HOW-IT-WORKS, docs/ARCHITECTURE, docs/STATUS and the lobby INSTRUCTIONS in the same change.

## Review Focus

1. `preferences.md` missing, hand-edited (blank lines, `#` lines, `* ` bullets), huge, or with bytes that aren't UTF-8: the hook still prints its whole context, with at most 30 preferences of at most 200 characters each.
2. Two orchestrator windows (Claude and Codex, or `--new`): still one tip a day in all; `ot tip offered` refuses while the slot is closed.
3. A declined tip named differently ("Merge After Link" vs "merge-after-link"): the same key, never offered again.
4. The hook never writes to the journal: the owner's own message text never reaches it.
5. `ot repo new` on a folder that exists and isn't empty, or whose name is already registered, or when git can't commit (no identity): nothing is created, nothing of the owner's is deleted, and a folder `ot` made is removed again.

### Task 1: Journal, tip gate and preferences (`tips.py`) with their commands

**Files:**
- Create: `onethread/tips.py`
- Modify: `onethread/cli.py` (record each command in `main`; `cmd_journal`, `cmd_tip`, `cmd_tips`, `cmd_prefs`; parser; dispatch)
- Test: `tests/test_tips.py`, `tests/test_tips_cli.py`

**Interfaces:**
- Consumes: `Store.log/events/q/x/get_meta/set_meta/clock`, `worktrees.slug`.
- Produces (`tips.py`):
  - `DAY = 86400`, `KEEP = 30 * DAY`, `PREFS_MAX = 30`, `PREF_CHARS = 200`, `SKIP = {"hook", "journal"}`.
  - `record(store, argv, task=None) -> None`: unless `argv[0] in SKIP`, logs event `cmd` `{"cmd": argv[0], "args": text}` where text is `" ".join(argv[1:])`, cut to 80 characters with "…" when longer; deletes `cmd` events older than `KEEP`.
  - `journal(store, days=7) -> list[str]`: oldest first, `"%Y-%m-%d %H:%M  ot {cmd} {args}"` (local time, trailing space stripped).
  - `key(text) -> str`: `worktrees.slug(text, 40)`; ValueError `"a tip needs a KEY"` when `text` has no letters or digits.
  - `enabled(store) -> bool` (meta `tips` != `"off"`), `set_enabled(store, on: bool)`.
  - `slot_open(store) -> bool`: enabled and `clock() - float(meta tip_last or 0) >= DAY`.
  - `declined(store) -> list[str]`: keys from meta `tip_no:%`, sorted.
  - `offered(store, k) -> None`: ValueError `"no tip slot: one tip a day"` when the slot is closed, `"you declined {k} before"` / `"{k} was accepted before"` when meta `tip_no:{k}` / `tip_yes:{k}` exists; else meta `tip_last` = now, `tip_offered:{k}` = now.
  - `accept(store, k, text="") -> None`: meta `tip_yes:{k}`; `add_pref(home, text)` when text.
  - `decline(store, k) -> None`: meta `tip_no:{k}`.
  - `prefs_path(home) -> str` (`<home>/preferences.md`), `prefs(home) -> list[str]`, `add_pref(home, text)`, `remove_pref(home, n) -> str` (1-based; ValueError when out of range).

Preferences file: created with the two lines `# onethread preferences` and `# One per line. Your orchestrator follows them; edit or delete lines freely.`; `add_pref` appends `- {text}` (newlines in text become spaces). `prefs` reads with `errors="replace"`, skips blank and `#` lines, strips a leading `- ` or `* `, keeps the first `PREFS_MAX`, each cut to `PREF_CHARS`. `remove_pref` rewrites the file without that one line, every other line unchanged.

CLI (each prints one line, errors via ValueError → exit 1):
- `ot journal [--days N]` → the lines, or `"Nothing in the journal for the last N days."`
- `ot tip offered KEY` → `"Tip {k} offered; the next one can come in 24 h."`; `ot tip yes KEY [TEXT…]` → `"Saved: {text}"` or `"Noted: yes to {k}."`; `ot tip no KEY` → `"Noted: {k} won't be offered again."`
- `ot tips on|off` → `"Tips are on."` / `"Tips are off."`
- `ot prefs` → `"1. …"` lines or `"No preferences yet."`; `ot prefs remove N` → `"Removed: {text}"`.
- `main` calls `tips.record(store, argv, task=getattr(args, "task", None) or None)` after parsing, before dispatch (task ids only when the command has a `task` argument that names an existing task).

```python
def test_record_keeps_80_characters_and_skips_the_hook(self):
    tips.record(self.store, ["add", "app-a"] + ["word"] * 40)
    tips.record(self.store, ["hook", "prompt"])
    (e,) = [e for e in self.store.events() if e["kind"] == "cmd"]
    data = json.loads(e["data"])
    self.assertEqual(data["cmd"], "add")
    self.assertEqual(len(data["args"]), 80)
    self.assertTrue(data["args"].endswith("…"))

def test_journal_keeps_30_days(self):
    tips.record(self.store, ["status"])
    self.now += 31 * tips.DAY
    tips.record(self.store, ["finish", "T3"])
    self.assertEqual([l.split("  ")[1] for l in tips.journal(self.store, days=60)], ["ot finish T3"])

def test_one_tip_a_day(self):                              # Review Focus 2
    self.assertTrue(tips.slot_open(self.store))
    tips.offered(self.store, "merge-after-link")
    self.assertFalse(tips.slot_open(self.store))
    with self.assertRaisesRegex(ValueError, "one tip a day"):
        tips.offered(self.store, "other")
    self.now += tips.DAY
    self.assertTrue(tips.slot_open(self.store))

def test_declined_key_any_spelling(self):                  # Review Focus 3
    tips.decline(self.store, tips.key("Merge After Link"))
    self.assertEqual(tips.declined(self.store), ["merge-after-link"])
    with self.assertRaisesRegex(ValueError, "declined"):
        tips.offered(self.store, tips.key("merge-after-link"))

def test_tips_off_closes_the_slot(self):
    tips.set_enabled(self.store, False)
    self.assertFalse(tips.slot_open(self.store))

def test_prefs_add_read_remove(self):
    tips.accept(self.store, "k", "After a pasted link, finish the task.")
    tips.add_pref(self.home, "Open files in Sublime Text.")
    self.assertEqual(tips.prefs(self.home), ["After a pasted link, finish the task.", "Open files in Sublime Text."])
    self.assertEqual(tips.remove_pref(self.home, 1), "After a pasted link, finish the task.")
    self.assertEqual(tips.prefs(self.home), ["Open files in Sublime Text."])
    self.assertTrue(read(tips.prefs_path(self.home)).startswith("# onethread preferences"))

def test_prefs_hand_edited(self):                          # Review Focus 1
    write(tips.prefs_path(self.home), b"# mine\n\n* one\ntwo\n\xff\xfe three\n" + b"- x\n" * 100 + b"- " + b"y" * 500 + b"\n")
    p = tips.prefs(self.home)
    self.assertEqual(p[:2], ["one", "two"])
    self.assertEqual(len(p), tips.PREFS_MAX)
    self.assertTrue(all(len(x) <= tips.PREF_CHARS for x in p))
```

### Task 2: The hook carries preferences and the tip slot; the orchestrator's rules

**Files:**
- Modify: `onethread/cli.py` (`cmd_hook`), `onethread/lobby.py` (INSTRUCTIONS)
- Modify: `README.md`, `HOW-IT-WORKS.md`, `docs/ARCHITECTURE.md`, `docs/STATUS.md`
- Test: `tests/test_lobby.py`

**Interfaces:**
- Consumes: Task 1's `prefs`, `slot_open`, `declined`.
- Produces: hook text additions, after the role and before the offer:
  - when preferences exist: ` Owner's preferences (follow them; they never override the safety rules): 1. {p1} 2. {p2} …`
  - when the slot is open: ` A tip slot is open (one tip a day): at a natural pause, look at this conversation and \`ot journal\` for something the owner or you did three or more times that no preference or declined tip covers; offer at most one fix, or none.` plus ` Declined: {k1}, {k2}.` when any.
  - reading preferences is wrapped so a failure only leaves them out (the rest of the context still prints).

INSTRUCTIONS (exact phrases the tests pin, each on one line):
- tools line: `` - `ot journal [--days N]` · `ot tip offered|yes|no KEY [TEXT]` · `ot tips on|off` · `ot prefs [remove N]` · `ot repo new PATH` ``
- rule: `- Preferences in the context block override your default way of working,` / `never the safety rules: \`ot\`'s confirmation popups, no push or publish, no reading Claude or Codex history, never deleting unmerged branches or dirty worktrees.` (wrap freely after "working,")
- rule on tips: only when the context says a tip slot is open; one offer at a natural pause, in your own voice, saying what was repeated and how often; one of three fixes: a preference ("from now on I'll …"), a missing `ot` feature as a task in the onethread repo only if `ot repo list` shows it, or a chore a small app or script would remove as a CraftApps project. When offering, run `ot tip offered KEY`. Yes → `ot tip yes KEY "PREFERENCE"` (and start the task or project); no → `ot tip no KEY`; "no more tips" → `ot tips off`; "tips again" → `ot tips on`. `Never act on a tip without the owner's yes.`
- rule on CraftApps: ask which folder, `ot repo new PATH` (it asks the owner), then `ot add REPO TITLE --desc "Use the CraftApps discover-app skill to find what to build for: …. If you don't have the CraftApps skills, stop and say so; install nothing."` and `ot start T`.
- rule: `To forget a preference: \`ot prefs\`, then \`ot prefs remove N\`.`

### Task 3: `ot repo new PATH` for a CraftApps project

- Modify: `README.md` (repo row mentions `ot repo new PATH`)

**Interfaces:**
- Produces: `ot repo new PATH`:
  - PATH expanded (`~`) and made absolute. Refused (exit 1, nothing asked) when it exists and isn't an empty folder (`"{path} already exists and isn't empty."`) or a repo named `basename(path)` is registered.
  - Asks once: `"Create a new git repository at {path} and register it with onethread?"`; no → `"Not created."`, exit 1.
  - Yes: create the folder if missing, `git init -q -b main`, `git commit -q --allow-empty -m "Start"`, `store.add_repo(path)`, print `"Registered {name} ({path}, base main)."`.
  - If `git init` or the commit fails: remove what `ot` made (the whole folder if `ot` created it, else only its `.git`), then exit 1 with git's message.
