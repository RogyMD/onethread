# Cast ("you are the boss") Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The owner picks who they are (`ot me Caesar`); the orchestrator becomes their right hand and every task's agent a named member of their circle. Finished work is cleaned up automatically (Task 6).

**Architecture:** A new `onethread/cast.py` owns the owner's identity, the cast roster and name assignment, on top of a `cast` table and a `cast_name` column on tasks. `prompts.py` turns cast data into persona lines; the CLI, hook, supervisor and views read them. `ot` never invents names: the orchestrator builds the cast with `ot cast set`, nudged by the prompt hook.

**Tech Stack:** Python 3.10+ standard library, SQLite, unittest.

**Spec:** `docs/superpowers/specs/2026-10-21-cast-design.md`

## Global Constraints

- Standard library only; no new dependencies.
- `ot`'s own output stays plain and exact: ids, statuses, errors, confirmations, commands, paths, numbers. The cast name is added, never substituted for title, repo or id.
- Worker JSON results stay machine-readable; only `summary` is in voice.
- Real people: light parody of style, never a claim to be them, never invented real-world claims about them or their circle.
- A missing cast never blocks work: unnamed tasks run normally.
- `plain` (or unset) = no roleplay and no cast names anywhere.
- `ot character` is removed; `ot me` replaces it. An existing `character` meta value becomes `me`.
- Every test run: `python3 -m unittest discover -s tests` from the onethread root, all green.

## Review Focus

1. `ot me` while tasks are running → open tasks lose their names, then get new ones on `ot cast set`; no task keeps a name from the old world. (Task 1 test `test_set_me_clears_names`.)
2. Cast JSON from the model is malformed (not JSON, missing `right_hand`, empty `members`, duplicate names, a member named like the right hand) → plain error, nothing half-saved. (Task 3 test `test_cast_set_rejects_bad_json_and_keeps_old_cast`.)
3. More tasks than members → extra tasks stay unnamed and the hook asks for `ot cast add`; a done task's name is reused. (Task 1 tests `test_fill_skips_when_no_free_member`, `test_done_task_frees_its_name`.)
4. Existing databases (schema 1, `character` set) open without errors and keep the owner's setting. (Task 1 test `test_old_database_migrates`.)
5. The owner says "switch to Cicero" → resolves by cast name, case-insensitive. (Task 4 test `test_resolve_by_cast_name`.)

### Task 6: Automatic cleanup

Spec: the "Addendum: automatic cleanup" section.

**Files:**
- Create: `onethread/cleanup.py`
- Modify: `onethread/engine.py` (`tick`), `onethread/cli.py` (`cmd_clean` replaces `cmd_prune`; parser), `onethread/worktrees.py` (`remove` deleted), `tests/test_worktrees.py` (its `remove` tests move to cleanup), `onethread/voice.py` (`dirty_worktree` template), `onethread/attention.py` (`KIND_WEIGHT["dirty_worktree"] = 1`), `onethread/lobby.py` (tools line), docs
- Test: `tests/test_cleanup.py`, `tests/test_cli.py`, `tests/test_engine.py`

**Interfaces:**
- Consumes: `worktrees.is_dirty`, `worktrees.is_merged(repo_path, branch, into)`, `model.label`.
- Produces:
  - `cleanup.LOG_DAYS = 7`, `cleanup.EVERY = 60` (seconds between automatic rounds).
  - `cleanup.size(path) -> int` — bytes under `path` (no symlink following; 0 if missing).
  - `cleanup.human(n) -> str` — `"1.4 GB"`, `"84 MB"`, `"12 KB"`.
  - `cleanup.clean(store, home, confirm=None, now=None, only=None) -> dict` with keys `worktrees` (ids), `branches` (names), `logs` (ids), `asked` (ids given a `dirty_worktree` offer), `freed` (bytes). For each done/cancelled task (or just `only`):
    - worktree set and clean → `git worktree remove --force` + `update_task(worktree="")`;
    - worktree dirty: `confirm is None` (automatic) → `add_attention(id, "dirty_worktree")` unless meta `keep_worktree:<id>` is `"1"`; `confirm` given → ask `"{label}'s worktree has uncommitted changes that will be lost. Delete it?"`, remove if yes;
    - worktree gone and branch merged into `base_branch` → `git branch -d` (never `-D`) + `update_task(branch="")`;
    - `runs/<id>` deleted when `confirm` is given (manual) or `now - task.updated > LOG_DAYS days`.
  - `Engine.tick` runs `cleanup.clean(self.store, self.home)` at most once per `EVERY` seconds (store clock).
  - `ot clean [T] [--keep]` — no task: `clean(..., confirm=ctx.confirm)`; with T: `only=T`; `--keep T` sets meta `keep_worktree:T` = `"1"`, closes its `dirty_worktree` attention and prints `Keeping {label}'s worktree.` Output: `Cleaned {n} worktrees, {b} branches and {l} logs; freed {human(freed)}.` or `Nothing to clean.`
  - `worktrees.remove` and `ot worktrees prune` are removed (cleanup owns removal).
  - `voice.PLAIN["dirty_worktree"] = "{label}'s worktree has uncommitted changes. Delete it, or keep it?"`.
  - Lobby tools line gains `ot clean [T] [--keep]`, and one rule: `"Clean up" means ot clean. For a dirty-worktree offer, "delete" means ot clean T, "keep" means ot clean T --keep.`
